# HOTD2 Arcade VR validation — 2026-10-25

This is the USA NAOMI `hotd2` cartridge adaptation. It does not use Dreamcast offsets, disc images or generated Dreamcast weapon assets. Physical headset testing has not been performed. Early gameplay and scripted OpenXR simulation establish the checks below; later chapters, bosses, endings, sustained headset performance and network sessions remain unverified.

## Media and setup

- The user's existing complete arcade cartridge and HOTD2-specific BIOS booted in the standalone native build. The cartridge has 21 unique files and 22 loader mappings, including its mirrored 2 MiB program ROM. No game data was downloaded.
- Actual ROM and BIOS bytes are read, length-checked and CRC-checked. The native BIOS check also covers region reloads. Dreamcast identifiers, alternate arcade program revisions, ordinary NAOMI BIOS and corrupt payloads are rejected.
- Android has its own identity `com.vrlightgunhub.hotd2arcade`, label HOTD2 Arcade VR and Hotd2ArcadeStartActivity library launcher. The setup scanner requires packed lowercase `hotd2.zip` plus `hod2bios.zip` or an embedded supported HOTD2 BIOS.
- Full Gradle `:flycast:test` passed: 58 tests, including 30 new HOTD2 file/status tests. Synthetic cartridge fixtures contain generated bytes with matching checksums, not ROM data.

## Measured native profile

Private render/RAM captures and SH4 disassembly established the following addresses for program CRC `b23d1a0c`:

| Purpose | Arcade address / behavior |
| :--- | :--- |
| Projection / viewport | `0x9C29A0` / `0x9C2AD8` |
| Camera vertical angle | 16-bit angle 7484 at `0x09A81A`; factor 3 widens about 41.1 to 96.7 degrees |
| Separate stock hit-test lens | `0x403438`; retained while the scene camera is widened |
| Player blocks | `0x3D0420`, stride `0x100`; native phase 5 active, 9 out |
| Lives / ammo / accepted shots | player offsets 16 / 36 / 52, six-round magazine |
| Shooting/story state | `0x3D0648`, 1 interactive / 0 story |
| Native gun input blocks | `0x3D17CC`, stride 36 |

Four guarded SH4 shifts preserve fifteen ADC bits. Verified live calibration maps both native axes over the whole framebuffer, with independent integer transcription within one pixel for all 640 X and 480 Y positions. It writes live RAM only. Persistent cabinet EEPROM calibration is left intact.

The native gun state/input regression passes 1,150 assertions, including unloaded/corrupt-code guards, invalid players, scene states, no partial patching, idempotence and both calibrations. The arcade media/credit regression passes 90 assertions, including the serialized credit initialization and Start-release edges across replay. Shared reload/input tests pass 23 cases.

## Arcade pistol and controls

- The native pistol is recognized by the CRC of its own 64 x 64 texture, rather than a fixed allocation address. No texture pixels are included in this source. Its complete pass contains 28 opaque and two translucent strips; topology and principal extents are checked before saving.
- First-run preparation presses Start once at the measured 30 seconds of game, then watches the opening scene. On this PC it captured a complete 57,892-byte HND1 model at about 19 wall seconds / 84 game seconds. Runtime loading reported four textures and 237 vertices. These timings are measurements, not a headset ETA.
- Cached restart bypassed preparation. A corrupt final cache plus a valid `.part` file did not bypass validation; automatic preparation rebuilt the final cache. B/Y skip returned to ordinary play without accepting that partial file. Shared gun builder/cache tests pass all 16 cases.
- The actual cartridge ran through native story and interactive phases in the OpenXR simulator. Both players joined and fired; six accepted shots emptied each magazine and produced six kicks. Further empty pulls produced no accepted-shot kick. Native reload restored ammunition.
- The paused Two players setting reversed P1/P2 hands. Both triggers were held across pause and the swap; no new accepted-shot kick occurred after the swap until release and a fresh pull. P2 leaving returned to one gun. Native story phases hid guns/laser and restored them when interaction resumed.
- The simulator's normal harness forces its simple gun for isolation; the final native-model scenario explicitly disables `vr.BuiltInGun` so the captured pistol is selected and rendered.

## Blood-color update (1.0.1)

The paused Blood color row selects Green or Red, saves vr.RedBlood immediately and applies it on the next cold game start. A pending choice shows (next start). A loaded snapshot always retains that reminder, because the snapshot can restore older effect resources.

The measured USA program reads the native cabinet blood byte at 0x0C3D109F in the resource selector at 0x0A34A6. Its mov.b @r3,r4 at 0x0A34AA supplies index0 for red resource193 (scr_blood_red.bin) or index1 for green resource194 (scr_blood_green.bin), using the native table at 0x140378. The adaptation substitutes only that input instruction with mov #0/#1,r4. Code, pointer and resource-table guards require the measured revision; unexpected words prevent every blood write. The override leaves cabinet data, EEPROM, difficulty, life and gun calibration untouched.

The selected index is latched at Event::Start, so changing the menu during play cannot mix already loaded effects. Its actual code write is included in the compatibility digest. Writes occur only when the word differs; native tests cover stock/red/green transitions, idempotence, every failed blood guard, unknown selector code, wrong game code and whole-RAM side-effect isolation. The native suite passes1172 checks, policy90, shared gun input23, model/cache16 and packaging43. Android JVM suite also passes.

Both cold-start OpenXR simulator runs passed: the native word became E401 for Green and E400 for Red exactly once; changing the paused menu saved the opposite choice, showed (next start), survived closing/reopening, and did not switch the active native index during the running game. Private captures and logs remain under build-win/vrtest/hotd2-blood-*; no game bytes are committed. The native cabinet byte remained1 in both runs. Physical headset checks remain pending.
